PlanMo データベース設計（Supabase PostgreSQL + RLS）
========================================

■ テーブル一覧
  profiles          id (= auth.users.id) / username / display_name / balance /
                    is_admin / 規約同意情報 ほか
                    ※ role列は廃止（0015）。全ユーザーが全ロールになれる
  ideas             title / description / genre / size_tier / images(複数) / status /
                    creator_id / modeler_id / price_physical / price_digital /
                    planner_rate / modeler_rate / platform_fee / stl_path /
                    delete_requested_by / delete_requested_at /
                    status_check CHECK制約でステータス値を限定
  orders            buyer / idea / type(physical|digital) / price / platform_fee /
                    shipping_name / postal_code / address / phone /
                    shipping_status / tracking_number / stripe_session_id ほか
  balance_history   user / amount / type(売上分配・ギフト交換 等) / expires_at(180日)
  exchange_requests user / exchange_type(Amazon|Apple|GooglePlay) / amount / status /
                    code（発行されたギフトコード）
  comments          idea / author / body
  idea_ratings      idea / user / stars(1-5)。1ユーザー1アイデア1票（上書き可）
  idea_favorites    user / idea（ほしいものリスト。複合PK）
  gift_stock        運営が登録した未使用ギフトコードの在庫
  announcements     運営からのお知らせ
  notifications     user / title / body / created_at（進捗通知）

■ RLS ポリシー方針
  - 全テーブル user_id ベース。自分のデータのみ操作可
  - カタログ（販売中・募集中アイデア）は全員読み取り可
  - アイデアの直接DELETEは権限剥奪済み。削除は
    request_idea_delete / confirm_idea_delete RPC（SECURITY DEFINER）経由のみ
  - idea_favorites は自分の分のみ select/insert/delete 可
  - 購入・分配は perform_buy / record_partner_order 系RPCでサーバー側ガード

■ 主要RPC
  request_idea_delete / confirm_idea_delete   削除の相互承認
  update_idea_status(p_idea_id, p_new_status, p_comment)  ステータス遷移ガード＋通知
  perform_buy / record_partner_order          購入・30%手数料・分配・履歴記録
  request_exchange                            ギフト在庫照合・即時発行 or 申請
  delete_my_account                           退会（profiles削除で連鎖削除）
  my_profile_stats                            評価数・平均・合計売上高（マイページ用）
  is_admin                                    管理者判定
