PlanMo 画面・機能仕様
========================================

■ 画面構成（タブ）
  PC: 上部タブバー / スマホ: 画面下部の固定タブバー（アプリ形式、全タブ常時表示）
  1. アイデア募集
  2. モデリング中
  3. 商品購入
  4. マイページ
  5. 売上・ギフト
  6. 運営管理（管理者のみ表示）

■ 1. アイデア募集
  - 投稿フォーム: タイトル / 詳細説明・仕様 / サイズ階級（S〜XLの選択式） / ジャンル /
    STL価格 / 複数画像アップロード（任意・AI画像より優先） /
    AI権利侵害チェック（Gemini API、結果は表示のみ） / プランナー・モデラー分配率（%）/
    プリント品価格はサイズ階級から自動決定
  - サイズ階級と最低価格（製造・配送費は購入者負担で別途）:
    S: 〜60mm角        最低 ¥1,000 ＋ 製造・配送費 ¥900
    M: 〜120mm角       最低 ¥2,000 ＋ 製造・配送費 ¥1,600
    L: 〜200mm角       最低 ¥4,000 ＋ 製造・配送費 ¥2,900
    XL: 200mm角超      最低 ¥8,000 ＋ 製造・配送費 ¥5,500
  - 募集中一覧はソート可能: ジャンル絞り込み＋新着順 / プリント品価格↑↓ /
    STL価格↑↓ / コメント数順 / 評価順
  - AI画像生成機能は実装済みだがAPIキー不備のため現在一時無効（権利チェックのみ有効）

■ 2. モデリング中
  - 制作中案件の一覧。モデラーが「引受」で参加（自分の投稿も引受可）
  - モデラーはSTLファイルをアップロードし「提出」→ ステータス「提出中」へ
  - プランナーが確認して「承認」（→販売中）or「修正依頼」（→制作中へ差戻し）
  - 修正依頼・取下げ時はコメント必須（摺り合わせ記録をコメント欄に残す）

■ 3. 商品購入
  - 販売中商品のカタログ。物理プリント品 / STLデータ の2種購入
  - ソート・ジャンル絞り込み対応
  - 購入は Stripe Checkout。初回決済時にカードが保存され、
    2回目以降は保存済みカードが選択された状態で開く（すぐ購入できる）
  - 商品カードにハート（🤍/❤️）ボタンで「ほしいものリスト」に追加

■ 4. マイページ
  - ステータスカード6枚: 投稿数 / 担当中モデリング数 / 売上残高 /
    受け取った評価数 / 平均評価 / 合計売上高
  - ほしいものリスト（ハートを付けた商品の一覧、クリックで詳細モーダル）
  - 投稿済みアイデア / 担当中案件 / 注文履歴・配送状況 / 残高変動履歴（180日期限付き）

■ 5. 売上・ギフト
  - 残高表示（180日有効期限つきポイント方式）
  - デジタギフト交換: Amazon / Apple / Google Play
    ・ギフト在庫プール方式の半自動化: 運営が事前購入したギフトコードを在庫登録し、
      同種・同額の在庫があれば即時発行、なければ未処理申請として手動処理
    ・最低交換金額 ¥1,000
  - 累計売上分配が¥1,000,000を超えると🔔で「確定申告のご案内」が自動表示

■ 6. 運営管理（管理者のみ）
  - KPIカード4枚＋サブタブ: 交換申請 / 製造・発送 / 注文一覧 / ギフト在庫 / お知らせ
  - 交換申請の承認処理（ギフトコード発行）、配送ステータス更新、
    アイデア管理（運営は削除の直接承認可）、お知らせ配信

■ 共通機能
  - アイデア詳細モーダル: 画像ギャラリー / 評価（★1〜5、1人1票・上書き可） /
    コメント欄 / 購入・ワークフローボタン
  - 🔔通知ボタン: 進捗通知（引受・提出・承認・修正依頼・削除依頼など） /
    運営からのお知らせ / 確定申告案内。未読時に赤丸表示
  - ⚙設定: アカウント名・メール・パスワード管理 ほか
  - 商品フロー中の削除は相互承認制（後述フロー参照）

■ アイデアのステータス遷移
  アイデア募集（モデラー募集中）
    → モデラー引受 → 制作中
    → STL提出 → 提出中
    → プランナー承認 → 販売中
    → 修正依頼 → 制作中へ差戻し
    → 販売後の「取り下げ」でも制作中へ戻せる
  削除: プランナー/モデラーの双方がいる案件は相互承認制
    （片方が削除リクエスト → 相手が承認して削除。
      未引受案件はプランナー単独削除可、運営は直接削除可）
  ※ 直接DELETEはDB権限レベルで禁止されており、削除は必ずRPC経由

■ 通知の宛先
  引受→プランナー / 提出→プランナー / 承認・修正依頼→モデラー /
  取下げ→モデラー / 削除リクエスト→相手側 / 削除完了→リクエスト者
